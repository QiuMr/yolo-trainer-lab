### 关键判断：不照抄 OCR-Studio 的更新机制

OCR-Studio 是 `bundle.active = false` 的免安装 zip，更新 = 覆盖整个目录（它自己写了
`updater.rs`：复制 exe 当 helper、等 PID 消失、覆盖、重启）。**本项目是 NSIS 安装版**，
覆盖会留下错误的注册表/卸载项，且 `externalBin` 的 144 MB 引擎在主进程运行时被占用。
→ 用官方 `tauri-plugin-updater` + minisign 签名，让真正的安装器接手。
**借鉴它但没抄它**的部分：版本号单一来源、固定 `latest.json` feed、发版全脚本化、
核对 Release 资产而不是读退出码、无 BOM JSON、网络失败收敛成一句话。

### 踩到的坑（都会误导判断）

- **NSIS 下 `createUpdaterArtifacts: true` 产出的是 `<setup>.exe` + `<setup>.exe.sig`，
  没有 `.nsis.zip`**。签名内容嵌进 `latest.json`，Release 只传 2 个资产。
  脚本最初按 zip 写，跑完打包看目录才发现。
- **`gh release create` 把资产名里的空格换成点**（`YOLO Trainer_…` → `YOLO.Trainer_…`）。
  后果：`latest.json` 里 `%20` 编码的 URL 必然 404，按本地文件名核对资产永远不匹配，
  脚本会误报"缺资产并补传失败"。→ 上传前复制成无空格名 `YOLO-Trainer_<ver>_…exe`，
  URL / 核对 / 补传统一用它。v0.1.0 是踩坑版，v0.1.1 是修正版。
- **`.sig` 其实带 `version:`**：base64 解码全文是
  `timestamp:…\tfile:…\tversion:0.1.0`。第一次只 `head -c 300` 看了前半段，误判成
  "不带版本"并写进文档，后来纠正并**启用 `requireSignedVersion`**（堵旧签名降级）。
  **判断签名格式必须解码全文，不能只看一段。**
- **平台键**：插件依次找 `windows-x86_64-nsis` → `windows-x86_64`，用通用键即可；
  `{{target}}` URL 变量的值其实只是 `windows`（不是带 arch 的全名）。
- **私有仓库的 Release 资产不能匿名下载**，客户端第一次检查就 404 → 必须 public（D021）。
- `.ps1` 老规矩：UTF-8 BOM + CRLF，写完用 PowerShell 转一遍再 `Parser::ParseFile` 验语法。

### 落地

- `git init -b main` + `.gitignore`（排除 22 GB artifacts / 144 MB 引擎 / 57 MB 上游源码 / 私钥），
  基线 472 文件 11.63 MiB；`gh repo create QiuMr/yolo-trainer-lab --public`。
- `build.rs` 读 `tauri.conf.json` 的 version 注入 `YOLO_TRAINER_VERSION`，断言三段数字；
  `version.rs` 提供数值比较（字典序下 `0.10.0 < 0.9.0` 是最经典的更新器 bug）。
- `updater.rs`：`check()` 永不抛错（失败进 `UpdateInfo.error`）；`install()` 重新 check 而不缓存
  `Update`（避免全局 state 的 Send/Sync 约束，也避免装到已被替代的版本），按百分比节流发事件。
- `UpdateCard.tsx`：挂载静默检查 + 6 h localStorage 缓存，**失败不缓存**；网络失败浅色句子，
  只有安装失败才用红框。
- `scripts/release.ps1`：校验干净/tag/私钥/externalBin → 构建 → 产物时间戳检查（防发旧包）→
  生成 `latest.json` → push/tag → gh release → 核对资产并补传。

## 白天 · 全面审查与修复（四路只读代理）

修了 5 处前端、6 处后端。两条是真 bug，不要当成风格问题：

1. **`App.tsx` 事件订阅泄漏**：`onEngineEvent(...).then(off => disposers.push(off))` 的清理函数
   会在 promise resolve 之前跑（StrictMode 每次挂载必现）。push 进已走过的数组 → 泄漏；下次挂载
   再注册一个 → **每个 epoch 折叠两次，loss 曲线翻倍**。正确写法是 `alive` 标志 + 迟到句柄当场
   注销。`PredictCard`/`SettingsPage` 早就这么写了，只有 `App.tsx` 漏了 —— **同一模式散落多处时
   必有漏网**，以后加订阅先搜一遍现有写法。
2. **`TrainPage` 只校验范围不校验整数**：壳侧 `epochs/batch/imgsz` 是 `u32`，前端 "1.5" 能过
   范围检查，然后在 serde 报 `invalid type: floating point 1.5, expected u32`。

其余：`PredictCard` 对话框期间未占位（可开两个对话框排两次推理）、拖放扫描无序号（慢的覆盖快的）、
`UpdateCard` 失败分支读闭包旧 `version`。

## 中午 · 续训与 ONNX 调研（未实现，结论进 D025）

用户问"能不能用训过的模型继续训、怎么免 Python 转 ONNX"。查了源码和真实产物，
**两项都没做**（用户明确说"只是问问，要做要好好商量方案"）。

硬事实，下次别再翻一遍：

- 三种产物：`exports/*.bpk` 3.16 MB（权重+架构元数据）/ `checkpoints/{best,last}` 24 MB
  （model.bin + ema.bin + optimizer.bin + manifest.json）/ 导出格式。差 7 倍全在 AdamW 动量。
- 续训两个入口语义不同，**极易搞错**：`--model x.bpk` = 微调，新 run、优化器清零；
  `--resume checkpoints/last` = 断点续训，继承 epoch/优化器/EMA/数据集配置。
  上游原话："A Burnpack initializes a new run; it is not a resumable optimizer checkpoint."
  壳层 `engine.rs` 只拼 `--architecture + --data`，**两个都没接**。
- ONNX **必须 Python，但不只是 Python**：`src/export/mod.rs` 注释明说 Burn 不能导 ONNX，
  Python 只负责"按 ultralytics 源码搭图 + torch.onnx.export"；权重名映射 Rust 侧已做完
  （`keymap.rs` + `burn_store::BurnToPyTorchAdapter`）。还要 torch==2.13.0（解压近 1 GB）
  和**一份姊妹目录的 ultralytics 源码**（不是 wheel）。`--no-verify` 只省 Burn 对比，
  ONNX Runtime 校验永远必跑。
- 免 Python 的正路是「骨架+填权重」：图与权重正交 → 我们侧导一次图、权重清零留 shape →
  客户端按 keymap 填。最省实现是 `--external-data always` 让骨架引外部 weights.bin，
  客户端只按 offset 写字节，不碰 protobuf。估 3~5 天，风险是骨架随上游漂移。

## 傍晚 · ONNX 两个阻塞全部解决，分类+检测都通了

用户拍板"改，对齐 ultralytics"，yolo26 要求"先查清楚再定"。结果两条都解决：

1. **检测头通道**：不是"公式不同"，是 `head.rs` 把 `nc` 写成了常量 `DEFAULT_NUM_CLASSES`。
   注释自己写着 `max(ch[0], min(nc,100))`，代码是 `p3.max(DEFAULT_NUM_CLASSES.min(100))`。
   更关键：`with_num_classes` 只改 num_classes、**不重算 cls_channels**，宽度构造时就定死 80。
   训练完全看不出来（多余通道闲置），只在导出时炸成 33 个 wrong-shape。
   修：`with_num_classes` 里同步重算，改 yolov8/yolo11/yolo26/yolov10（yolo12 复用 yolo11）。
2. **yolo26 双头**：`forward()` 只走 one2one，`head.o2m_*` 只被 `forward_train_dual` 用 →
   o2m 是训练辅助头，推理图不消费。修：snapshot.rs 加
   `PathFilter::new().with_predicate(|p,_| !p.contains("o2m_"))`。
   **坑**：`PathFilter` 默认 `new()` 是"不匹配任何路径"，且 `match_all` 时谓词被忽略，
   必须在默认值上显式换 filter。没选"让 Python 审计忽略该前缀"——那等于改测试迁就产物。

实测（全部 ORT 校验通过 + 骨架 max|diff|=0）：
- 分类 3 类 6.17 MB / 202 节点 / 80 张量
- yolov8n 检测 3 类 11.7 MB / 375 节点 / 127 张量
- yolo26n 检测 3 类 9.77 MB / 514 节点 / 204 张量
