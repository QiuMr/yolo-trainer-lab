### 单图推理

- `predict.rs`：引擎的 `predict --json` 把"人类日志 + 多行 JSON + 人类摘要"混在一个流里，

### 关键判断：不照抄 OCR-Studio 的更新机制

OCR-Studio 是 `bundle.active = false` 的免安装 zip，更新 = 覆盖整个目录（它自己写了
`updater.rs`：复制 exe 当 helper、等 PID 消失、覆盖、重启）。**本项目是 NSIS 安装版**，
覆盖会留下错误的注册表/卸载项，且 `externalBin` 的 144 MB 引擎在主进程运行时被占用。
→ 用官方 `tauri-plugin-updater` + minisign 签名，让真正的安装器接手。
**借鉴它但没抄它**的部分：版本号单一来源、固定 `latest.json` feed、发版全脚本化、
核对 Release 资产而不是读退出码、无 BOM JSON、网络失败收敛成一句话。

### 踩到的坑（都会误导判断）

- **NSIS 下 `createUpdaterArtifacts: true` 产出的是 `<setup>.exe` + `<setup>.exe.sig`，
  没有 `.nsis.zip`**。签名内容嵌进 `latest.json`，Release 只传 2 个资产。
  脚本最初按 zip 写，跑完打包看目录才发现。
- **`gh release create` 把资产名里的空格换成点**（`YOLO Trainer_…` → `YOLO.Trainer_…`）。
  后果：`latest.json` 里 `%20` 编码的 URL 必然 404，按本地文件名核对资产永远不匹配，
  脚本会误报"缺资产并补传失败"。→ 上传前复制成无空格名 `YOLO-Trainer_<ver>_…exe`，
  URL / 核对 / 补传统一用它。v0.1.0 是踩坑版，v0.1.1 是修正版。
- **`.sig` 其实带 `version:`**：base64 解码全文是
  `timestamp:…\tfile:…\tversion:0.1.0`。第一次只 `head -c 300` 看了前半段，误判成
  "不带版本"并写进文档，后来纠正并**启用 `requireSignedVersion`**（堵旧签名降级）。
  **判断签名格式必须解码全文，不能只看一段。**
- **平台键**：插件依次找 `windows-x86_64-nsis` → `windows-x86_64`，用通用键即可；
  `{{target}}` URL 变量的值其实只是 `windows`（不是带 arch 的全名）。
- **私有仓库的 Release 资产不能匿名下载**，客户端第一次检查就 404 → 必须 public（D021）。
- `.ps1` 老规矩：UTF-8 BOM + CRLF，写完用 PowerShell 转一遍再 `Parser::ParseFile` 验语法。

### 落地

- `git init -b main` + `.gitignore`（排除 22 GB artifacts / 144 MB 引擎 / 57 MB 上游源码 / 私钥），
  基线 472 文件 11.63 MiB；`gh repo create QiuMr/yolo-trainer-lab --public`。
- `build.rs` 读 `tauri.conf.json` 的 version 注入 `YOLO_TRAINER_VERSION`，断言三段数字；
  `version.rs` 提供数值比较（字典序下 `0.10.0 < 0.9.0` 是最经典的更新器 bug）。

- `UpdateCard.tsx`：挂载静默检查 + 6 h localStorage 缓存，**失败不缓存**；网络失败浅色句子，
  只有安装失败才用红框。
- `scripts/release.ps1`：校验干净/tag/私钥/externalBin → 构建 → 产物时间戳检查（防发旧包）→
  生成 `latest.json` → push/tag → gh release → 核对资产并补传。
