## AI 操控接口第二轮（后端，未动 UI）

目标：好用 + 不误导。决策 D030，契约 docs/API.md 第 9 节。

**新增**
- `src/runs.rs` —— 扫 `runs/<task>/<run>/`，`results.csv` **按列名**解析（表头随任务变），
  task/classes 取 `config.resolved.json` 的 `model.task` / `model.class_names`。
- `GET /runs?limit=N` —— 重启后找旧模型的唯一途径（`/state` 是进程内快照，重启即 idle）。
- `POST /datasets/scan` —— 路径放 body，中文免 percent-encode。
- `RunState.last_fitness`、`/state?since` 的 `reset` / `truncated` 字段。
- `settings::normalize_device()` —— device 白名单唯一来源（引擎 spawn 与 HTTP 共用）。

**修的误导**
- `accepted.device` 回显生效值（曾回显请求原文，`gpu`→`auto` 调用方无感），改写进 `warnings`。
- `/predict` 按责任方分 400/500（引擎崩溃曾报 400，客户端一直调参数）。
- `/stop` 无训练时 `stopped:false`（曾假报 true）。
- `/train` 预检任务×数据集格式（与 `models.ts::taskProblem` 同规则）；扫描器不认的格式放行。

**测试** 43 → **60 passed / 0 failed / 3 ignored**。新增 8 项真 HTTP（起真实监听端口，
按 Content-Length 读响应）+ 5 项 runs + 3 项 runstate。clippy 新增代码零警告。

**坑**
- 按 mtime **秒级**排序会让同秒的 run 退化成按名字排；排序用完整 `SystemTime`，展示才降级。
- Windows 回环上 `read_to_end` 会报 `ConnectionReset`：数据其实收全了，是服务端关闭时内核还有
  未读字节发 RST。测试必须按 `Content-Length` 精确读（curl/reqwest 就是这么做的）。

## AI 接口第三轮：真实端到端测试 + 三个缺陷（2026-11-13 深夜，D031）

**方法上的教训**：第二轮做了 8 条 HTTP 测试，全是"单端点"。补一条串起全流程的测试后，第一次跑
就 420 秒超时失败 —— 单个端点全绿不等于链路可用。

**暴露的缺陷（都不是新写的代码，是长期存在）**：

1. **折叠逻辑在 Tauri `setup` 里**。hub 是 `Vec<mpsc::Sender>` 扇出，但 `runstate` 的更新靠
   `lib.rs` 的窗口订阅线程。没有窗口的进程（测试、将来的 headless）里 `/train` 返回 202、
   引擎在训练，而 `/state` 永远 `idle`、`seq` 永远 0。修法：`Runtime::new` 自己订阅折叠。
   **注意**：折叠线程必须持 `Weak<Inner>`，持 `Arc` 会让 Runtime 永不释放、线程永挂。
2. **`reset()` 把状态打回 `idle`**。`202` 到引擎第一个 `start` 事件之间有几十秒初始化，
   调用方在这窗口里看到 `idle` 会重发 `/train` → 409。改为 `begin(epochs)`：置 `running`、
   填 `total_epochs`、**不动 `seq`**（没事件就不能推进 cursor）。
3. **引擎启动失败会卡在 `running`**。改为 `fail()` 经 `apply` 记 `error{code:"spawn_failed"}`，
   `/events` 里也看得到。

**并发**：每连接一线程、超时 30s，轮询不加间隔能把线程堆起来。加 64 上限 + RAII 计数，
超限 503。两个坑：`thread::spawn` 创建失败会 panic 掉 accept 循环（必须用 `Builder::spawn`）；
拒绝前要先 `read` 排空客户端已发数据，否则内核发 RST，调用方看到"连接被重置"而不是 503。

**路径写法不一致**：`/runs` 的 `best` 用 `\` 拼，`/state` 是引擎原样输出（`/`）。
不要字符串比较，用 `canonicalize`。已在 API.md 记录。

**实测数据**：e2e 3.5 秒跑完（health→scan×2→400→stop→train→poll→runs→predict），
tiny-dataset 1 epoch 得 `loss=4493 / fitness=0.0` —— 又一次「loss 有值但 mAP=0」。
`cargo test --lib` 62 passed / 4 ignored。

（端口、`%APPDATA%\com.yolotrainer.desktop\control-token`、六步 PowerShell 流程、
代理绕回环与 503 退避两个坑）。
