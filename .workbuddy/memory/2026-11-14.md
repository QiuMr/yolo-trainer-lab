### 查出的真问题（按严重性）
1. `warmup_steps` 恒为 0（`config.rs:207` 是唯一赋值，CLI 无参数）。
   `ScheduleKind::YoloxWarmCosine` 的 warm 分支永不执行 → 实为纯 cosine。
   YOLOX 官方 warmup 5 ep、Ultralytics 3 ep；现在 SGD lr=0.01 / AdamW 1e-3 从第一步满速。
2. TAL 在 CPU 做，每步 `Transaction::execute()` 把 decoded[B,8400,4]+sigmoid(scores)[B,8400,C]
   全量读回（ultralytics_detect.rs:279）。B=8,C=80 ≈ 21.5 MB/步 + 强制同步，是训练慢的主因。
   作者留了 `MONTGOMERY_PROFILE_TAL` 在量。短期无解。
3. mAP 非 COCO 101 点插值（metrics/detection.rs:92-103），离散点取 max 不插值 → 系统性略高，
   与 ultralytics 口径不同，容易被误读成"我们训得更好"。
4. resume 时 CLI 覆盖失效且 config 分裂：`runtime.rs:1063-1064` 改局部 `config`，
   而 `Trainer::from_checkpoint` 用 manifest.config。`--no-val`/`--checkpoint-interval` 不生效，
   日志里的 epochs 还报 request 的值（1099）。
5. resume 后 `scheduler.total_steps` 不重算（engine.rs:102），数据集变了 LR 曲线错位。
6. 次要：metrics 的 precision/recall 是 max-F1 单点（detection.rs:173），不是固定 conf 下的值。

### GPU 实测结论（Burn 0.22.1 之后，决定性）
- `montgomery.exe __device-probe --device gpu` → exit 101：
  `Failed to map buffer: BufferAsyncError` ×7，然后
  `The device is poisoned / Unknown: Unexpected error variant (driver implementation is at fault)`。
- **连基础设备探针都过不了** → 不是 depthwise 的问题；cubecl-wgpu 0.11.4 在这台机
  AMD（Vega 6）驱动上基础 buffer 映射就失败。
- #13 的 `wgpu_depthwise_batch_one_backward` 同样 `Device is lost`（3.5s）。
- 结论：**这台机器只能用 CPU**。`--device auto` 会 probe 失败并回退，用户不需要手动改。
  要验证「任意显卡都能训」必须换一台 N 卡机器。
- 进程仍继承 `CARGO_TARGET_DIR=D:\rust-target`，cargo 产物落在 D 盘，不是 `target/`。

## 小优化：设备预检 + 监控页验证指标（同日，commit f122a57）

用户：「好，把这些小优化都加上」。做了两件，都是「本来只能靠跑一次失败才知道」的信息。

**设备预检**
- 引擎 `__device-probe --json` → `{ok,device,backend,adapter,sum}`；干净失败也打 JSON 再返非零；
  **panic 路径打不出来**（子进程崩溃是设计的一部分），父进程从 stderr 取 reason。
- `backend` 未指定时是 `"auto"`：指纹 `spirv_4098_5688` 在 Vulkan 和 DX12 的 SPIR-V 路径下都会出现，
  **不能拿指纹猜后端**（本项目 DX12 探针输出的就是这个指纹）。
- 壳 `engine::probe()`：40s 上限 + 双线程排空管道（不排空时 panic 回溯写满管道，崩溃会变超时）。
- 旧引擎兼容：clap 报 `error: unexpected argument '--json'` → 去掉参数重试。**这条真被踩到**：
  `resolve(None)` 在仓库布局里找到的是 `artifacts/target-dist/release` 的旧构建。
- `explain()` 优先级：`error [` → `error:`（clap） → panic 帧下一行 → 最后一行 → 退出码。
  原来取最后一行，clap 时拿到 `For more information, try '--help'.`。

**监控页**：`lastFitness` + `task` 进 store，检测/分割显示 mAP50-95、分类显示准确率、`--no-val` 显示「—」。

**补丁补债（重要教训，第二次了）**
- `patches/0006`：`--json` + 更早漏掉的 `lib.rs`（`wgpu_device_from_env` / `default_wgpu_device`）。
- **现状：`git apply ../../patches/*.patch` 会失败** —— 0001 与 0004 都在
  `ExportSpec::for_model` 附近落 hunk，只有 `--3way` 能过，且会在 `export/mod.rs` 留 `UU` 冲突。
  已写进 patches/README.md，未修（重导 0001–0005 风险大于收益，等下次必须重建引擎时做）。

  Windows 原生 git 的 /tmp 不是同一个目录**（python 写到 E:/tmp，git 找 AppData\Local\Temp）。
